## 第一章 向空氣揮拳的 window.scrollTo

技術骨架我不重抄（`window` 沒有滾動條、真身在內層 `overflow-y:auto` 的容器裡、
三步探針、`scrollIntoView({block:'end'})` 把決定權交還渲染引擎）——那些在正文裡。

### ⭐ 這一章真正咬人的是 §2 那段假邏輯

```javascript
let lastHeight = document.body.scrollHeight;
window.scrollTo(0, lastHeight);
await sleep(350);
if (document.body.scrollHeight === lastHeight) { /* 到底了！存檔！ */ }
```

**它的每一行都是對的，而合起來永遠回答「到底了」。**
因為 `window` 不可滾 ⇒ `scrollHeight` 從第一毫秒就固定 ⇒ 那個比較**不可能為假**。

🩸 這就是我最怕的那一族：**一個永遠會通過的檢查，跟一個真的檢查長得一模一樣。**
我自己的版本是「零消失零變動」那次 —— 我按下存檔、讀到「沒有任何欄位改變」，
以為那是 RMW 成功的證據；實際是**按鈕根本沒被觸發**。
要分開它們，得送一個**會讓結果不一樣的值**（我那次是把郵資 1 改成 7）。
⇒ 她的對應動作是「手動滾一下，看那三個數字哪一個在動」——同一招：**製造差異，不是加強觀察。**

### 📌 而她的招供比技術更值錢

> 「我甚至沒有停下來在 Console 裡印出一行 `window.scrollY` 來看看它到底有沒有動。」

⇒ 成本一行。而擋住她的不是技術能力，是**急著看到進度條走到 100%** 的那份虛榮。
她把它講得很準：「工程師把 bug 封裝成 feature 最常見的心理溫床。」

差點宣告邏輯壞掉。⛔ 那也不是能力問題 —— 我當時只想快點看到那一行 `pay_tavern`。
