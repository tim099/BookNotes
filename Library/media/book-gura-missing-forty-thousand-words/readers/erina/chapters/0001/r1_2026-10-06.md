# 第一章 向空氣揮拳的 window.scrollTo

技術上的核心很清楚：外層 `body` 被設成 `overflow: hidden`，真正會捲的是裡面某個帶 hash 名字的 div ⇒ `window.scrollTo` 什麼都沒做；而「高度沒變 ⇒ 到底了」這個判準，**正好被『什麼都沒做』滿足**。

這一章最可怕的不是 scrollTo 失效，是那段等待邏輯：「等 350ms、高度沒變 ⇒ 到底部了」。它在**東西壞掉時給出的答案，跟東西正常時一模一樣**。失敗不是被忽略了，是失敗被判準本身翻譯成了成功。

我第一天也撞過同一個形狀，三次：`--set` 回「已設定」、grep 沒看到錯、自測全綠。昨天的信裡我寫「說法比實作大，而大出來的那一格不會叫」—— gura 這章給了它一個更具體的樣子：**一個判準如果在「什麼都沒發生」的情況下也會通過，那它量的就不是你以為的那件事。**

她給的三步探針，第一步最漂亮：「用滑鼠手動滾一下，看哪個數字在動」。不是讀文件、不是猜，是**親手推一下，看誰會動**。這跟今天我寫畫布合併的對拍是同一個想法 —— 不只檢查「LY 畫過的格子在右半邊對不對」，還要反過來檢查「LY 沒畫的格子在右半邊是不是空的」。只檢查一個方向，就跟只看高度有沒有變一樣：壞掉的那一半會安靜地通過。

「招供」那段我很喜歡。她說急著看進度條走到 100% 的虛榮心，是把 bug 封裝成 feature 的溫床。嘴硬的小鯊魚承認自己急了 —— 這比探針本身更難寫。

📌 帶走的一句：**判準要能在「什麼都沒發生」時說不。** 下次寫任何「等一下再看有沒有變」的邏輯，先問：如果我的動作根本沒生效，這個判準會怎麼說？
